# AmoCRM Client for PHP

Мини-проект для интеграции с [amoCRM](https://www.amocrm.ru/) через OAuth 2.0 и API v4.
Это не только пример авторизации: проект показывает, как построить небольшой прикладной
клиент CRM с локальной синхронизацией контактов, поиском дублей и обработкой webhook-событий.

Проект создан как портфолио-кейс, демонстрирующий работу с внешним API, токенами,
многопользовательским контекстом, SQLite, кэшированием, пагинацией, retry-логикой и
нормализацией данных.

## Возможности

- OAuth 2.0: обмен authorization code на пару токенов, хранение и обновление `access_token`.
- Автоматическое обновление токена при истечении срока действия или ответе API `401`.
- Работа с несколькими аккаунтами amoCRM через отдельный пользовательский контекст.
- Получение информации об аккаунте, контактов, сделок и пользовательских полей.
- Создание контактов и сделок с поддержкой custom fields.
- Автоматическая обработка ошибок валидации amoCRM: исправление типов чисел и дат,
  удаление неподдерживаемых пользовательских полей и повтор запроса.
- Синхронизация контактов из amoCRM в локальную SQLite-базу с постраничной загрузкой.
- Поиск дублей контактов по системным полям (`PHONE`, `EMAIL`) и custom fields.
- Нормализация значений перед сравнением: телефоны, email, числа и текст.
- Webhook-обработка добавления, изменения и удаления контактов.
- Автоматическая проверка нового контакта на дубли и добавление заметки со ссылками на найденные записи.
- Кэширование метаданных пользовательских полей.
- Ограничение частоты запросов до 7 запросов в секунду и повтор запросов при `429`/ошибках сервера.
- Генерация массовых тестовых контактов для проверки синхронизации и дедупликации.

## Стек

- PHP 8.3
- cURL для HTTP-запросов к API amoCRM
- PDO и SQLite для хранения токенов, аккаунтов, контактов и индексов поиска
- Docker или встроенный PHP-сервер
- amoCRM API v4 и OAuth 2.0

## Как выглядит сценарий

1. Пользователь открывает приложение и запускает авторизацию в amoCRM.
2. `auth.php` принимает OAuth callback, сохраняет аккаунт и токены в SQLite.
3. Клиент получает данные аккаунта, контакты, сделки и доступные custom fields.
4. Контакты можно синхронизировать локально и проверять на совпадения по выбранным полям.
5. После авторизации для аккаунта регистрируется webhook на события контактов.
6. При добавлении контакта webhook обновляет локальную копию, ищет дубли и при необходимости
   добавляет в amoCRM заметку с результатами проверки.

## Быстрый старт

### Требования

- PHP 8.3+ с расширениями `curl`, `pdo` и `pdo_sqlite`;
- либо Docker Desktop;
- зарегистрированная интеграция в amoCRM с `client_id` и `client_secret`.

### Настройка окружения

Скопируйте `.env.example` в `.env` и заполните значения:

```env
AMO_CLIENT_ID=your_client_id
AMO_CLIENT_SECRET=your_client_secret
AMO_REDIRECT_URI=http://localhost:8000/auth.php
AMO_BASE_DOMAIN=your-account.amocrm.ru

AMO_BASE_URL=http://localhost:8000
WEBHOOK_URL=https://your-public-domain.example/webhook-contacts.php

DB_HOST=localhost
DB_NAME=amocrm_oauth
DB_USER=your_mysql_user
DB_PASS=your_mysql_password
```

Для локального запуска `AMO_REDIRECT_URI` должен совпадать с callback URL интеграции в
amoCRM. Значение `WEBHOOK_URL` должно быть публичным HTTPS-адресом: amoCRM не сможет
доставить webhook на `localhost`.

### Запуск локально

```bash
php -S 0.0.0.0:8000 -t public
```

Откройте [http://localhost:8000](http://localhost:8000).
SQLite-база и нужные таблицы создаются автоматически при первом запуске приложения.

### Запуск через Docker

```bash
docker build -t amocrm-client-php .
docker run --rm -p 8000:8000 -v "$(pwd):/app" amocrm-client-php
```

После запуска откройте [http://localhost:8000](http://localhost:8000).

## Основные страницы и endpoints

| Путь | Назначение |
| --- | --- |
| `public/index.php` | Главная страница и выбор аккаунта для работы |
| `public/auth.php` | OAuth callback, logout, смена аккаунта, принудительное обновление токена и webhook установки интеграции |
| `public/callback.php` | Проверка авторизации, информация об аккаунте, списки контактов/сделок и формы создания сущностей |
| `public/duplicates.php` | Выбор полей и поиск дублей в локальной базе |
| `public/webhook-contacts.php` | Приём событий добавления, изменения и удаления контактов |
| `public/sync.php?user=<id>` | Синхронизация контактов выбранного аккаунта в SQLite |
| `public/generate-test-contacts.php` | Генерация тестовых контактов пакетами |

## Архитектура

```text
public/                  HTTP-точки входа и demo-интерфейс
    index.php
    auth.php
    callback.php
    duplicates.php
    webhook-contacts.php
src/
    OAuthClient.php       OAuth и API-клиент amoCRM
    HttpException.php     HTTP-ошибки API
    logger.php             Серверное логирование
    Storage/               Абстракция хранения и SQLite-реализация
config/                   Сбор конфигурации из .env
data/                     Скрипты и путь к SQLite-базе
storage/                  Логи приложения
views/                    Переиспользуемые PHP-шаблоны
```

`OAuthClient` отделяет работу с API от хранения данных через `StorageInterface`. Сейчас
по умолчанию используется `SqliteStorage`; интерфейс позволяет заменить его на другую
реализацию хранения без изменения публичных методов клиента.

## Конфигурация

Основной конфиг собирается в `config/config.php` из `.env`:

| Переменная | Назначение |
| --- | --- |
| `AMO_CLIENT_ID` | ID интеграции amoCRM |
| `AMO_CLIENT_SECRET` | Секрет интеграции amoCRM |
| `AMO_REDIRECT_URI` | OAuth callback URL приложения |
| `AMO_BASE_DOMAIN` | Домен аккаунта amoCRM, например `account.amocrm.ru` |
| `AMO_BASE_URL` | Базовый URL приложения |
| `WEBHOOK_URL` | Публичный URL endpoint для webhook контактов |
| `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASS` | Параметры, подготовленные для альтернативного MySQL-хранилища |

Токены и данные аккаунтов по умолчанию сохраняются в `data/database.sqlite`. Файлы
`.env`, SQLite-база и логи исключены из Git через `.gitignore`.

## Ограничения demo-версии

Это учебный и портфолио-проект, а не готовый production-модуль. Перед развёртыванием в
реальном окружении необходимо как минимум:

- вынести секреты и OAuth-токены из SQLite в защищённое хранилище или зашифровать их;
- добавить отдельную проверку подписи/секрета webhook и защиту от повторной доставки;
- закрыть служебные endpoints (`sync.php`, генерацию тестовых данных и операции смены аккаунта)
  серверной авторизацией и проверкой прав;
- добавить CSRF-защиту для state-changing browser-запросов и строгую валидацию входных данных;
- не выводить OAuth-токены в интерфейс и не записывать секреты в логи;
- настроить HTTPS, безопасные cookie, security headers и production-уровень обработки ошибок.

Эти ограничения обозначены намеренно: цель репозитория — показать архитектурный подход и
интеграцию с API amoCRM, а не скрыть границы демонстрационной реализации.
